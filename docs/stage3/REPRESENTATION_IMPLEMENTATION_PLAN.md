Citation evidence: **2 437 863** наблюдений ссылок, из них **406 811** `exact_doi`, **223** `ambiguous_doi`, **2 030 829** `unresolved`. Число `exact_doi` — количество **наблюдений**, не утверждение о 406 811 уникальных рёбрах. Raw cited-reference lists у APA RIS **не предоставлены**: это `not_exposed`, а не нуль цитирований. Из PubMed источника сохранены **86 book-family**, APA — 3 `Retracted Article` и 19 `Peer-Reviewed Status-Unknown`, WoS — 413 `NR/CR` mismatch с gap 584. Флаги не терять и не объявлять автоматически критериями исключения.

Любая линза строится по **canonical_article_id**, а не по 87 511 строкам источников. Перечень допустимых статей (`article_eligibility_policy`: journal-only versus сохранённые books) и политика выбора конфликтующих title/abstract значений между источниками — научные решения владельца; до них не подменять текст самым длинным или произвольно приоритетным. Сначала отчёт о покрытии текстом: `both_title_abstract`, `title_only`, `abstract_only`, `missing_both` по базе, family, году, флагам и каждой canonical group; агрегаты данных здесь **не измерены**.

## 2. Единый промежуточный контракт

`text_input.parquet`: `corpus_release_id, article_id, chosen_source_record_id, title, abstract, language, text_policy_id, source_record_ids, has_title, has_abstract, text_sha256, access_class`. Возможные конфликты выбора текста вынести в отдельный `text_conflict_report`.

`citation_graph_nodes.parquet`: полный approved `article_id` roster, `family`, `has_observed_outgoing_reference_list`, `has_resolved_in_or_out_edge`, `isolate_reason` (`coverage_unknown` / `no_observed_resolved_edge` / другое без научного вывода).

`citation_graph_edges.parquet`: `source_article_id, target_article_id, edge_provenance_refs, raw_reference_count, unique_edge_key, source_coverage`, только по `exact_doi` со связью к source_record + ordinal + raw SHA. Сохранить отдельно `ambiguous_citations` (223) и `unresolved_citations`; никакой arbitrary target, никакого заполнения APA ссылок. **Открыто владельцу:** направленный или ненаправленный graph для node2vec и вес/дедупликация повтора ссылки в нескольких исходных базах. До решения можно **сравнивать варианты в пилоте**, не закрепляя научный основной graph.

Каждый compute asset обязан иметь: `asset_type, asset_id, input_artifact_ids, corpus_release_id, code_ref, config_ref, model_ref_id (nullable), model_identity_hash (nullable), runtime_environment_ref, seed_policy, output_uri/hash, quality_report_id, status, created_at, computation_signature`. Model-backed => non-null immutable `model_identity_hash`. Никаких перезаписей принятых outputs. Для model identity: HF repository + **full immutable revision** + file digests, tokenizer/adapters digests, library/runtime lock; не `main` как scientific ID. Для non-model graph `model_ref_id/model_identity_hash=null`.

Выход каждой линзы: `article_embeddings.parquet` (или Arrow shards): `article_id, representation_artifact_id, lens_id, vector: fixed_size_list<float32>[dim], text_or_graph_coverage_status, model_identity_hash, config_ref, input_hash`. Отсутствующий вектор — явный `missing`, не нулевой/fake vector. `neighbours.parquet`: `representation_artifact_id, article_id, neighbor_article_id, rank, distance_or_similarity, metric, k, filter_policy, index_ref, exact_or_ann`, отдельный набор для каждой линзы; сравнивать только на пересечении eligible/observed articles. Neighbour overlap — сравнение методов, **не независимая научная валидация**. Валидация ANN — измерение recall@k относительно exact subset или полного exact как предписано архитектурой.

## 3. Линзы и ещё не утверждённые параметры

### PubMedBERT — semantic
**Уже принято:** title + abstract → **768-d article vector**, точная схема **MetSyn**; минимальная модельно-совместимая нормализация, без автоматического stemming/lemmatization. **Не выдумывать:** в доступных документах Pro_Adherence/MetSyn нет точных `preprocessing`, `max_length/overflow`, `tokenizer`, `pooling` (CLS vs masked-mean etc.), порядок/title separator, нормализация вектора и точный checkpoint; их надо получить из действующего MetSyn code/config либо утвердить владельцем до самого первого полноценного расчёта. **Кандидаты к идентификации**, но НЕ объявленные принятыми модельными весами: `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract` (бывший PubMedBERT abstracts) и `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract-fulltext` (бывший PubMedBERT abstracts+fulltext); обе базовые модели 768 hidden, max sequence 512. Точное соответствие MetSyn требует проверки. [Official model card](https://huggingface.co/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract) / [fulltext variant](https://huggingface.co/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract-fulltext).

**Проверка:** frozen text selection, корректные missing/truncation counts, `N×768`, все конечные числа, deterministic eval/no grad, model/tokenizer revision and digest, reference MetSyn embeddings on the same sample *если доступны*, CPU/GPU numerical-tolerance report. Выбор pooling не должен возникать из benchmark производительности.

### node2vec — structural
**Уже принято:** **node2vec**, именно на citation graph; DeepWalk и GraphSAGE сняты как primary alternatives. **Предварительная техническая конфигурация только для benchmark**, не научный default: `dim=128, walk_length=40, walks_per_node=10, context_window=10, p=1, q=1, epochs=1, seed=20261031`. Для sensitivity минимум вариант `p/q` при фиксированном графе и 2–3 random seeds; окончательные `p,q,dim,weight,direction/isolate` — владелец. Сохранить graph_snapshot_id, deterministic sorted node mapping, edge dedup policy, seed, exact package versions, walker implementation, `graph_hash`, isolated component policy. Directed versus symmetrised training нельзя менять без отдельного scientific config. [Original Stanford reference defaults](https://github.com/snap-stanford/snap/blob/master/examples/node2vec/node2vec.cpp) (80 walk length, 10 walks/node, 128 dim, p=q=1) — это только **внешний технический ориентир**, не утверждённые параметры.

**Проверка:** отсутствие edge без verified target, отсутствие self-loop/duplicate policy anomalies, 223 ambiguous DOI не стали рёбрами; подсчёт unique graph edges, component/isolates, degree distributions по данным и источникам; seed sensitivity и same-config deterministic replay/tolerance. Нельзя объяснять изоляцию отсутствием цитирований в реальном мире при неполных источниках. Если node2vec не даёт осмысленного вектора изолированному узлу, фиксировать `missing_structural`.

### SPECTER2 — semantic + citation-trained prior
**Уже принято:** отдельная SPECTER2 lens; она **не подменяет** PubMedBERT и node2vec. Модель использует title+abstract при inference; её структурный компонент происходит из **citation-informed pretraining**, а не из подгрузки текущего citation graph Stage2. **Технический кандидат**: `allenai/specter2_base` + proximity/retrieval adapter `allenai/specter2`, для статьи `title + tokenizer.sep_token + abstract`, truncation max_length=512, первый токен last_hidden_state. [Official SPECTER2 documentation](https://github.com/allenai/SPECTER2) / [model card](https://huggingface.co/allenai/specter2_base). **Требует фиксации** base+adapter revisions/digests, `transformers`/`adapters` compatible versions и owner-approval для proximity adapter как scientific task variant; другие adapters означают другую lens configuration. При обычной BERT-base конфигурации ожидается 768 dim, подтвердить непосредственно по pinned model config до исполнения.

**Проверка:** exact base/adapter identity, тест `title/abstract` concatenation и 512-token truncation, `N×dim`, no NaN, same-revision reproducibility, сравнение neighbourhood coverage отдельно от семантической/структурной линз. Не использовать собственный citation graph как ещё один вход SPECTER2 без научного решения.

## 4. Порядок реализации и stop/go

**Gate P0 (сейчас, без compute):** закрепить restricted Drive frozen input IDs/hashes и существующий Stage2 release; специфицировать schema, IDs, coverage and missing rules; выяснить точный MetSyn implementation contract и model variant; выписать открытые научные решения. Проверки: контракт не переписывает corpus, все поля имеют source provenance, нет DOI target при ambiguity, все три lens families описаны отдельно. **GO** только к подготовке пилота после протокола MetSyn и разрешения владельца; **STOP** при неидентифицированной MetSyn-схеме.

**Gate P1 (один малый пилот, только после разрешения):** **примерно 1 000 canonical групп**, детерминированная стратификация source presence, год, journal/book, abstract availability, citation degree/isolation и APA flags; одна малая component graph neighbourhood при необходимости проверяет edge cases. Сначала проверить input coverage и graph census, затем inference PubMedBERT и SPECTER2 последовательно, node2vec два seed-повтора на одном graph config. Измерять tokens/article, p50/p95 truncation, docs/sec, peak CPU/GPU RAM, walltime, dollars=0 при бесплатной среде, output bytes. Не трактовать 1 000 как научный discovery sample.

**Gate P1 checks:** 100% expected article_id coverage *как статус* (включая missing), никакой дубликации id, zero nonfinite vectors, 100% source lineage, identity hash и правильная размерность, traceable edge counts, 0 ambiguous auto-targets; partial text/graph coverage измерены, не считаются `zero`; repeat within numerical tolerance, node2vec seed variation quantified. Ручная внешняя содержательная проверка фиксированной небольшой выборки (без возврата лицензированных текстов в публичные артефакты). **STOP** при invalid model pin, неверном graph target, невоспроизводимом input/ID alignment, memory overflow или недоступной лицензии/правомерном compute location.

**Gate P2 (отдельная санкция на полный run):** последовательные offline runs с чанками/checkpoints, `PubMedBERT` → `SPECTER2` → `node2vec` либо изменение очередности по измеренному ресурсу. Каждый — отдельный immutable asset с собственным manifest. Порча одной линзы не инвалидирует готовый snapshot другой. Подготовить index/exact-neighbour computation specs для будущего Stage4; сравнение top-k neighbour sets на общем observed coverage (не валидирует ни одну линзу). Только после полного private readback/hashes и developer проверки разными методами — QA04 на крупном интегрированном рубеже. Нет автоматического Stage transition/release.

## 5. Ресурсы: инженерная оценка, не измеренный benchmark

Пусть `N=57 293`. Векторный float32 PubMedBERT **57 293×768×4=176 004 096 B ≈168 MiB**; SPECTER2 с dim 768 столько же; node2vec с **предложенными**, ещё не принятыми 128 dims: **29 334 016 B ≈28 MiB**. Вместе только raw floats ≈**364 MiB**, **без** source inputs, schema/IDs, ANN index, metadata, checkpoints, weights или graph/walk buffers. Полная попарная матрица `N×N×4` ≈**13.1 GB** — не materialize; использовать индекс или блочное exact-kNN. Для `k=20` одни пары id+score (8+4 байт) около 13.8 MB на линзу, плюс metadata/index.

| Задача | Пилот | Полный объём: предварительная вилка | Ресурсный риск |
|---|---|---|---|
| Таблица текстовых входов + graph | метаданные ~1k и edge checks | 1–4 h CPU подготовки/проверок | 16 GB RAM минимум, 32 GB комфортно; 10–25 GB свободного scratch |
| PubMedBERT inference | 1k статей, CPU либо бесплатная GPU | GPU ~0.5–3 h; CPU заметно дольше (~6–36 h) | ~8–16 GB VRAM на batch 8–32/до 512 tokens, 16–32 GB host RAM |
| SPECTER2 inference | 1k статей после model pin | GPU ~0.5–3 h; CPU ~6–36 h | batch/VRAM примерно аналогично PubMedBERT; base + adapter |
| node2vec | 1k sample graph для API/seed checks; графовая репрезентативность ограничена | ~0.5–8 h CPU, сильно зависит от edge aggregation/walk corpus | 16–32 GB RAM ориентир, Python graph object может увеличить потребление |
| Neighbours | exact sample и ANN recall audit | ~0.5–3 h после vectors | RAM ~8–16 GB, без полной dense N×N матрицы |

Значения времени — **оценки сценария**, не обещания. Batch length, GPU type, missing abstracts, model adapter и реализация walks изменяют скорость на порядок. Экстраполяция только из реального P1: `T_full ≈ T_pilot × (N_eligible/N_pilot_eligible)` для transformer lane + загрузка моделей/фиксированный overhead; для node2vec повторно оценить на полном графе — малый подграф не доказывает full-graph memory profile.

**Расходы:** вариант A — локальная CPU/GPU или бесплатный одолженный/институциональный compute: **$0 внешних счетов** (время/электроэнергия не нулевые). Вариант B — отдельный разрешённый одноразовый remote GPU: ориентир текущих оферт 16GB RTX A4000 от **$0.25/h** и 24GB L4 от **$0.49/h** ([Runpod A4000](https://www.runpod.io/gpu-models/rtx-a4000), [L4](https://www.runpod.io/gpu-models/l4), цены/доступность зависят от региона и типа), условные 2–10 GPU-hours ≈ **$0.5–$5** *только GPU* плюс CPU/диск/выгрузка/хранение. Эта сумма **не является одобренным бюджетом, live quote или оценкой полной стоимости**. Restricted WoS/APA тексты **нельзя отправлять внешнему провайдеру** без отдельной проверки лицензии/права доступа и решения владельца. Никакого автоматического provisioning/billing.

## 6. Важные дефекты/смещения и раздельная валидация

- **Text missingness / selection bias:** абстракт отсутствует у части корпуса; политику title-only и конфликтов источников утверждать отдельно. Качество neighbour similarity и coverage сравнивать стратифицированно, отсутствие не маскировать.
- **Citation observation bias:** APA no cited-reference lists, WoS 413 NR/CR inconsistencies; node2vec graph reflects *observed resolved links*, не полную сеть. Наличие/отсутствие edge нельзя использовать для вывода о неизмеренной исторической citation activity.
- **DOI ambiguity:** 223 наблюдения ссылки без unique target; не добавлять в graph; хранить `ambiguous_doi`.
- **Family/retraction:** 86 book-family сохранены, APA retractions/unknown flags не исчезают. Решение включения в научный article-only universe остаётся owner-level.
- **SPECTER2 independence:** обученность на citation relations НЕ независимая проверка node2vec; сравнение линз — объект анализа. Внешняя manual relevance/held-out validation должна содержать evidence, не использованное при построении соответствующей линзы.
- **Randomness:** node2vec seed sensitivity не считать нулевой; фиксировать версию runner, зависимости, численные допуски и порядок article IDs.
- **Serving/privacy:** derived vectors и source text в restricted Drive, не на public GitHub. Публичный сайт и release — отдельный будущий Stage decision.
