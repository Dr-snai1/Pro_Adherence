Отчёт `text_conflict_report` фиксирует выбранную базу, понижение приоритета из-за отсутствия abstract, долю title-only и исключительные случаи, по canonical group, без смешивания полей. ## 2. Единый промежуточный контракт

`text_input.parquet`: `corpus_release_id, article_id, chosen_source_record_id, title, abstract, language, text_policy_id, source_record_ids, has_title, has_abstract, text_sha256, access_class`. Возможные конфликты выбора текста вынести в отдельный `text_conflict_report`.

`citation_graph_nodes.parquet`: полный approved `article_id` roster, `family`, `has_observed_outgoing_reference_list`, `has_resolved_in_or_out_edge`, `isolate_reason` (`coverage_unknown` / `no_observed_resolved_edge` / другое без научного вывода).

`citation_graph_edges.parquet`: направленный исходный граф наблюдаемых связей `source_article_id → target_article_id` только из verified `exact_doi`, с `edge_provenance_refs`, счётчиком наблюдений, ссылками на source record+ordinal+raw SHA, без искусственного заполнения APA. **Для утверждённой node2vec training projection** тот же graph преобразуется в **ненаправленные уникальные пары** (unordered article IDs), **вес каждого ребра = 1**, повторные наблюдения в PubMed/WoS/APA не повышают вес. Сохранять `observation_count` и provenance отдельно от веса. Исключать self-loops в node2vec. Оригинальные направления и наблюдаемые self-citations оставлять отдельным immutable graph asset для прямых цитирований, co-citation и других классических библиометрических анализов; исключение self-loops действует только для node2vec training graph. Исключённые `ambiguous_citations` (223), unresolved, self-loops и coverage учитывать в отчёте; никогда не подставлять произвольные DOI targets. Эти параметры **утверждены владельцем 2026-11-10**, не проводить обязательный пилот directed/undirected или weighted/unweighted.

Каждый compute asset обязан иметь: `asset_type, asset_id, input_artifact_ids, corpus_release_id, code_ref, config_ref, model_ref_id (nullable), model_identity_hash (nullable), runtime_environment_ref, seed_policy, output_uri/hash, quality_report_id, status, created_at, computation_signature`. Model-backed => non-null immutable `model_identity_hash`. Никаких перезаписей принятых outputs. Для model identity: HF repository + **full immutable revision** + file digests, tokenizer/adapters digests, library/runtime lock; не `main` как scientific ID. Для **самого citation_graph** как non-model asset `model_ref_id/model_identity_hash=null`; **обученный node2vec embedding — model-backed asset**, его run/trained-model identity (точный graph snapshot + настройки, seed, реализация и checksums) обязана быть закреплена в non-null `model_ref_id/model_identity_hash` согласно общему compute-контракту.

Выход каждой линзы: `article_embeddings.parquet` (или Arrow shards) с `article_id, representation_artifact_id, lens_id, text_or_graph_coverage_status, model_identity_hash, config_ref, input_hash`. **Для PubMedBERT CLS и Mean** хранить три разных поля конечного вектора статьи: `raw_article_vector: float32[768]` (до L2, со всей исходной длиной и направлением), `raw_l2_norm: float64` (вычисленная по raw), `unit_article_vector: float32[768]` (после L2); оба варианта имеют независимые идентичности и provenance. Исходный raw **не перезаписывать** нормализованной копией. Основной индекс/соседи: **cosine similarity по unit_article_vector**; нормализация строго **ПОСЛЕ** объединения всех фрагментов, не по частям. Для missing — null vector и null norm, не нули. `neighbours.parquet`: `representation_artifact_id, article_id, neighbor_article_id, rank, distance_or_similarity, metric=cosine, k, filter_policy, index_ref, exact_or_ann`, отдельно для каждой PubMedBERT-ветви и остальных линз с их собственными контрактами; сопоставимость сравнивать на пересечении eligible/observed articles. Neighbour overlap не является независимой научной проверкой. Валидация ANN — recall@k относительно exact.

## 3. Линзы и ещё не утверждённые параметры

### PubMedBERT — semantic
**Зафиксировано решением владельца 2026-11-09:** PubMedBERT Base, предобученная только на аннотациях PubMed (а не abstract+fulltext), размерность 768; из последнего скрытого слоя получаем **ДВА самостоятельных вектора: CLS и masked mean**, оба храним и проверяем отдельно; вход title + собственный маркер-разделитель токенизатора + abstract; не более **512 токенов на один проход**, длинный текст разбивается на фрагменты, без незаметного удаления хвоста; **fine-tuning не выполняем**. MetSyn не копируется. Технический кандидат модели: `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract` (бывший PubMedBERT-abstract), бесплатные веса MIT; точную immutable revision, tokenizer и SHA нужно закрепить до вычислений. [Model card](https://huggingface.co/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract). Принято два pooling-режима, **ни один пока не выбран в качестве единственного основного**.

**Проверка:** одинаковые статьи, текст и токенизация для двух pooling-конфигураций; два `N×768` артефакта, конечные числа, тест правильного CLS и masked mean; **для Mean маска содержит только обычные токены текста, исключая CLS, SEP, остальные специальные символы и padding**. CLS-ветвь берёт последний hidden state токена CLS. Корректный разделитель, неусечённый охват длинного текста и численные проверки; без fine-tuning.

### Приоритет источника PubMed → WoS → APA (утверждено 2026-11-09)

Сначала рассматривать **целые записи** canonical group с title и abstract; выбирать первую по приоритету PubMed, затем WoS, затем APA. При отсутствии complete записи — брать первую запись с title по тому же порядку (с явным флагом `title_only` только когда abstract действительно нет ни в одной записи). Не смешивать название из одной базы с аннотацией из другой автоматически. Иные пограничные случаи маркировать для адресной обработки, не заводить новый обязательный этап согласования для каждой статьи. Техническая функция `choose_pubmedbert_source_priority` детерминированно формирует выбор. Сохранять source_record_id, исходный порядок базы и причину fallback, считать распределение выбранных текстов по базам.

### Статьи без аннотаций — вариант В (утверждено 2026-11-09)

Если хотя бы одна исходная запись canonical group содержит abstract, не допускать вычисление по одному названию автоматически: нужен явно выбранный корректный исходный текст/правило конфликта между базами. Если **ни одна** исходная запись не содержит abstract, но есть title — вычислить **два** независимых PubMedBERT-вектора `CLS` и `masked_mean` по одному title, сохранив `text_state=title_only` и `title_only_vector=true`; отсутствие abstract не восстанавливается и не маскируется. Если отсутствует и title, установить `missing_input` и null vector. Не назначать title-only штраф/искусственную весовую поправку и не исключать такие статьи без отдельного научного решения.

**Отчёт после разрешённого расчёта:** отдельные абсолютные числа/проценты title-only от **57 293 canonical articles**, от eligible и от готовых PubMedBERT-векторов; помимо этого — число случаев `requires_source_resolution`, когда выбранный title-only источник имеет другой source record с аннотацией. Разбивка по году, source family и типу записи; отдельно показать качество / контекст ближайших публикаций для title-only на позднем этапе оценки, без запуска отдельного пилота для принятия решения. Сохранить lineage выбранного source record, versioned config и фактический текстовый статус. Никакой процент не считать до обработки реальных данных.

### Длинные аннотации — утверждённая методика 2026-11-09

**Решение владельца:** вариант **Б, без отдельного сравнительного пилота А/Б**. При длине input >512 токенов формировать несколько фрагментов, **предпочитая границы завершённых предложений**; каждый фрагмент — отдельный inference того же frozen PubMedBERT Base. Для обеих самостоятельных ветвей CLS и masked mean рассчитывать итоговый вектор статьи **как средневзвешенное векторов фрагментов**, вес каждого фрагмента — **число его содержательных токенов** (без padding и специальных служебных токенов). Более короткий остаточный фрагмент влияет меньше. **Не сравнивать А и Б перед использованием, не подменять Б простым равным средним.**

**Реализация:** точным tokenizer модели определить бюджет в 512 токенов, включая CLS/SEP и маркер после названия; greedily собирать последовательные предложения, пока следующий полный sentence не переполнит бюджет, затем начинать следующий chunk. Если отдельное предложение длиннее свободного бюджета нового чанка — делить **только этот случай** по границам токенов и считать такие вынужденные разрезы. Содержимое обрабатывать **целиком, в исходном порядке**. Не делать дублирующих перекрытий и повторного учёта токенов; в техническом baseline название появляется один раз в первом фрагменте и не повторяется в следующих, чтобы не изменять вес заголовка искусственно. Перед inference ещё раз проверить фактическую длину целиком закодированного chunk <=512. Если токенизация по границам предложения даёт изменившееся число токенов при склейке, перепаковать; не обрезать текст молча. Учитывать смещения token start/end и число содержательных токенов. Строго проверить полное покрытие: каждый исходный смысловой токен ровно один раз.

**Ограничение методики:** это сохранение текста без усечения, а не математически эквивалентное чтение всей статьи в одном контексте Transformer. Вес по длине для CLS тоже является принятой исследовательской эвристикой; она не объявляется оптимальной или доказанно лучшей.

**Обязательный отчёт по фактической обработке полного корпуса (после выполнения разрешённого расчёта):**

- Единица — **canonical article**, а не 87 511 исходных строк. Использовать неизменный roster **57 293** и прозрачную дополнительную базу «статьи, для которых вообще есть пригодный текст»; отдельно «с доступной аннотацией». Отсутствующую аннотацию не считать короткой.
- Для каждого article_id сохранить `abstract_token_count` (без названия), `full_title_separator_abstract_token_count` (с учётом специальных токенов), `requires_multiple_chunks`, `fragment_count`, `forced_sentence_splits`, `content_tokens_covered`, `content_tokens_expected`, `coverage_status`, frozen tokenizer/version и selected source id; само содержимое в публичный отчёт не включать.
- Показать **два независимых счётчика**: (1) сколько аннотаций *сами по себе* содержат >512 токенов, (2) сколько статей потребовали >1 фрагмента, потому что **весь вход** title+separator+abstract (+ special tokens) превышает 512. Показать абсолютные числа и проценты **от 57 293**, **от всех обработанных статей с текстом** и **от статей с имеющейся аннотацией**. Для каждой доли явно указать знаменатель, без скрытого изменения cohort.
- Гистограмма количества фрагментов (1, 2, 3, 4+), сколько предложений пришлось вынужденно разрезать; медиана и P95 длины полного входа по tokenizer. При необходимости отдельно по source presence, publication year и отсутствию abstract, чтобы выявить систематическое смещение.
- Проверка: 100% article_id coverage/status, 0 потерь/дублирования смысловых токенов в chunking, корректная сумма весов, оба CLS/Mean outputs имеют длину 768. Сохранить закрытый aggregated отчёт с config/model/hash/provenance. Отчёт формируется **автоматически как часть реального прогона**, а не как новый пилот или отдельный этап согласований.
- **После расчёта:** 03 сообщает владельцу фактическую долю и распределение. Владелец по этим данным решает, возвращаться ли к выбранной методике. **Не назначать заранее произвольный порог процентов** и не возвращаться автоматически к развилке без такого решения.

### Научное сравнение настроек PubMedBERT

Теперь не открытая развилка: PubMedBERT abstracts-only Base 768, CLS и masked mean параллельно из последнего слоя, title+sep+abstract, 512 за проход, предложение как граница фрагментов и длиновое взвешивание, без дообучения. Mean исключает служебные токены/padding, CLS — отдельная ветвь. Title-only — только если abstract отсутствует во всех источниках, с явным статусом, без штрафа; источник PubMed → WoS → APA с предпочтением полной записи. **Принято 2026-11-09: L2-нормализация только после полного article vector, cosine similarity для основной меры близости, сохранение raw float32[768] + raw L2 norm + normalized unit float32[768] для каждой CLS/Mean-ветви**. Вопрос L2/cosine закрыт. Исследование значения длины и направления — [отдельная необязательная научная ветвь](./EMBEDDING_GEOMETRY_SUBSTUDY.md), не блокирующая product.

**Проверка научных представлений:** CLS и masked mean рассчитываются на одних и тех же публикациях; вариант Б для длинных текстов, без пилотного сравнения A/B. У каждого финального raw article vector сохранять норму до преобразования и отдельный unit vector; проверить размерность 768, конечность, положительность нормы, |unit|≈1, raw≈norm×unit в допуске float32, после агрегации, отсутствие подмены raw. Для основных соседей metric=cosine. После full run содержательная экспертная оценка CLS и Mean на зафиксированном наборе; межлинзовое согласие не доказывает валидность. [Геометрический под-анализ](./EMBEDDING_GEOMETRY_SUBSTUDY.md) добровольный и может быть запущен позже.

### node2vec — structural
**Уже принято владельцем (2026-11-10):** одна основная конфигурация node2vec: `dim=128`, `p=1`, `q=1`, `walk_length=40`, `walks_per_node=10`, `context_window=10`, `epochs=1`, `seed=20261031`; **ненаправленный training graph** на уникальных неупорядоченных парах подтверждённых цитирований с бинарным `weight=1` и без self-loops. **Исходные направленные citation links сохраняются** отдельным графом без потери provenance. Изолированные/непредставленные в наблюдаемой сети статьи получают `missing_structural`/null, без искусственных связей или fake-zero vectors; отсутствие APA cited references не равняется отсутствию научных связей. На каждую реально полученную 128-мерную node2vec embedding сохранить **raw vector до нормализации, raw L2 norm, отдельный unit vector**; основное сходство — **cosine на L2-normalized output**; не уничтожать исходный масштаб/направление. Научно принятая конфигурация — **стартовая, не утверждение оптимальности** одной эпохи или длины маршрута. Код и отчёты должны фиксировать графовый snapshot/hash, directed/undirected derivation, source edges/counts, deterministic ID mapping, implementation/library versions, seed, exact config, isolate count, vector completeness и численные проверки. Дополнительная техническая проверка устойчивости и seed-replay не превращается в отдельный научный пилот; менять значения без нового методологического решения нельзя. DeepWalk и GraphSAGE не входят в основные модели.

**Проверка:** 100% source→canonical provenance и только exact DOI targets; никаких ambiguity→edge или fake APA links; повторные источники не меняют binary weights; направленный source и ненаправленный training graph сохраняются раздельно с совпадающим числом учтённых наблюдений; 0 duplicated undirected pairs / 0 self loops в training graph; графовая connectedness и isolated statuses в отчёте, явный `missing_structural`, не нулевой вектор. Для node2vec output — dim=128, finite raw/norm/unit, norm>0, unit≈1, raw≈norm×unit, metric=cosine. Проверить deterministic replay и как минимум seed sensitivity при плановом пилоте; результат seed-проверки не означает поиск альтернативного p/q. Не интерпретировать отсутствие observed links как доказательство отсутствия реальных цитирований.

### SPECTER2 — semantic + citation-trained prior
**Уже принято:** отдельная SPECTER2 lens; она **не подменяет** PubMedBERT и node2vec. Модель использует title+abstract при inference; её структурный компонент происходит из **citation-informed pretraining**, а не из подгрузки текущего citation graph Stage2. **Технический кандидат**: `allenai/specter2_base` + proximity/retrieval adapter `allenai/specter2`, для статьи `title + tokenizer.sep_token + abstract`, truncation max_length=512, первый токен last_hidden_state. [Official SPECTER2 documentation](https://github.com/allenai/SPECTER2) / [model card](https://huggingface.co/allenai/specter2_base). **Требует фиксации** base+adapter revisions/digests, `transformers`/`adapters` compatible versions и owner-approval для proximity adapter как scientific task variant; другие adapters означают другую lens configuration. При обычной BERT-base конфигурации ожидается 768 dim, подтвердить непосредственно по pinned model config до исполнения.

**Проверка:** exact base/adapter identity, тест `title/abstract` concatenation и 512-token truncation, `N×dim`, no NaN, same-revision reproducibility, сравнение neighbourhood coverage отдельно от семантической/структурной линз. Не использовать собственный citation graph как ещё один вход SPECTER2 без научного решения.

## 4. Порядок реализации и stop/go

**Gate P0 (сейчас, без compute):** сохранить frozen Stage2, immutable PubMedBERT abstracts-only Base, обе CLS/Mean ветви, вариант Б фрагментов, Mean без специальных токенов, title-only, приоритет PubMed → WoS → APA, а также **утверждённые L2-после-агрегации и cosine**. Сохранение raw vector+norm+unit vector — обязательный output contract, даже если дополнительный [под-анализ геометрии](./EMBEDDING_GEOMETRY_SUBSTUDY.md) не будет запущен. Пограничный случай title-only против abstract-only остаётся явным статусом. Финансы/Stage — по общим правилам; необязательный анализ геометрии ничего не блокирует.

**Gate P1 (один малый пилот, только после разрешения):** **примерно 1 000 canonical групп**, детерминированная стратификация source presence, год, journal/book, abstract availability, citation degree/isolation и APA flags; одна малая component graph neighbourhood при необходимости проверяет edge cases. Сначала проверить input coverage и graph census, затем inference PubMedBERT и SPECTER2 последовательно, node2vec два seed-повтора на одном graph config. Измерять tokens/article, p50/p95 truncation, docs/sec, peak CPU/GPU RAM, walltime, dollars=0 при бесплатной среде, output bytes. Не трактовать 1 000 как научный discovery sample.

**Gate P1 checks:** 100% expected article_id coverage *как статус* (включая missing), никакой дубликации id, zero nonfinite vectors, 100% source lineage, identity hash и правильная размерность, traceable edge counts, 0 ambiguous auto-targets; partial text/graph coverage измерены, не считаются `zero`; repeat within numerical tolerance, node2vec seed variation quantified. Ручная внешняя содержательная проверка фиксированной небольшой выборки. **STOP** при invalid model pin, неверном graph target, невоспроизводимом input/ID alignment, memory overflow.

**Gate P2 (отдельная санкция на полный run):** последовательные offline runs с чанками/checkpoints, `PubMedBERT` → `SPECTER2` → `node2vec` либо изменение очередности по измеренному ресурсу. Каждый — отдельный immutable asset с собственным manifest. Порча одной линзы не инвалидирует готовый snapshot другой. Подготовить index/exact-neighbour computation specs для будущего Stage4; сравнение top-k neighbour sets на общем observed coverage (не валидирует ни одну линзу). Только после полного private readback/hashes и developer проверки разными методами — QA04 на крупном интегрированном рубеже. Нет автоматического Stage transition/release.

## 5. Ресурсы: инженерная оценка, не измеренный benchmark

Пусть `N=57 293`. PubMedBERT: raw + unit CLS и Mean float32 2×2×57 293×768×4≈**672 MiB**, исходные нормы двух ветвей float64 ≈0.9 MiB; SPECTER2 с предварительными dim=768 ≈**168 MiB**; node2vec с принятыми 128 dims и обязательными **двумя** float32 vectors raw + unit ≈**56 MiB** плюс float64 raw norm ≈0.44 MiB. Итого dense floats ≈**896 MiB** плюс norms/metadata/index/shards/graph/provenance/models (верхняя оценка по полному 57 293 roster). Полную N×N попарную матрицу float32 ≈13.1 GB не материализовать. L2 и cosine не требуют второго прогона обучения/inference.

| Задача | Пилот | Полный объём: предварительная вилка | Ресурсный риск |
|---|---|---|---|
| Таблица текстовых входов + graph | метаданные ~1k и edge checks | 1–4 h CPU подготовки/проверок | 16 GB RAM минимум, 32 GB комфортно; 10–25 GB свободного scratch |
| PubMedBERT inference | 1k статей, CPU либо бесплатная GPU | GPU ~0.5–3 h; CPU заметно дольше (~6–36 h) | ~8–16 GB VRAM на batch 8–32/до 512 tokens, 16–32 GB host RAM |
| SPECTER2 inference | 1k статей после model pin | GPU ~0.5–3 h; CPU ~6–36 h | batch/VRAM примерно аналогично PubMedBERT; base + adapter |
| node2vec | 1k sample graph для API/seed checks; графовая репрезентативность ограничена | ~0.5–8 h CPU, сильно зависит от edge aggregation/walk corpus | 16–32 GB RAM ориентир, Python graph object может увеличить потребление |
| Neighbours | exact sample и ANN recall audit | ~0.5–3 h после vectors | RAM ~8–16 GB, без полной dense N×N матрицы |

Значения времени — **оценки сценария**, не обещания. Batch length, GPU type, missing abstracts, model adapter и реализация walks изменяют скорость на порядок. Экстраполяция только из реального P1: `T_full ≈ T_pilot × (N_eligible/N_pilot_eligible)` для transformer lane + загрузка моделей/фиксированный overhead; для node2vec повторно оценить на полном графе — малый подграф не доказывает full-graph memory profile.

**Расходы:** вариант A — локальная CPU/GPU или бесплатный одолженный/институциональный compute: **$0 внешних счетов** (время/электроэнергия не нулевые). Вариант B — отдельный разрешённый одноразовый remote GPU: ориентир текущих оферт 16GB RTX A4000 от **$0.25/h** и 24GB L4 от **$0.49/h** ([Runpod A4000](https://www.runpod.io/gpu-models/rtx-a4000), [L4](https://www.runpod.io/gpu-models/l4), цены/доступность зависят от региона и типа), условные 2–10 GPU-hours ≈ **$0.5–$5** *только GPU* плюс CPU/диск/выгрузка/хранение. Эта сумма **не является одобренным бюджетом, live quote или оценкой полной стоимости**. Никакого автоматического provisioning/billing. **Выбранный вычислительный режим:** закрытый анализ для собственного исследования на локальной машине или одноразово арендованном компьютере, без передачи текста стороннему сервису генеративного ИИ и без публикации исходных записей. Арендованный компьютер технически означает размещение рабочей копии данных на этой машине, но не передачу данных в публичный API. Дополнительные повторяющиеся этапы проверки лицензий, юридические gate или отдельное разрешение на каждый технический шаг не включаются в рабочий pipeline. Расходы на платный compute остаются отдельным решением владельца.

## 6. Важные дефекты/смещения и раздельная валидация

- **Text missingness / selection bias:** утверждено сохранять title-only статьи с явным статусом. После обработки измерять `title_only_count` и проценты от всего canonical roster, eligible и ready vectors, в разрезе года, исходной базы и типов публикаций. Проверить содержательно качество окружения title-only статей отдельно, чтобы видеть эффект неполноты текста, **без автоматического исключения или штрафа**. Если abstract имеется в другой исходной записи, запись не признаётся title-only до разрешения политики выбора текста.
- **Citation observation bias:** APA no cited-reference lists, WoS 413 NR/CR inconsistencies; node2vec graph reflects *observed resolved links*, не полную сеть. Наличие/отсутствие edge нельзя использовать для вывода о неизмеренной исторической citation activity.
- **DOI ambiguity:** 223 наблюдения ссылки без unique target; не добавлять в graph; хранить `ambiguous_doi`.
- **Family/retraction:** 86 book-family сохранены, APA retractions/unknown flags не исчезают. Решение включения в научный article-only universe остаётся owner-level.
- **SPECTER2 independence:** обученность на citation relations НЕ независимая проверка node2vec; сравнение линз — объект анализа. Внешняя manual relevance/held-out validation должна содержать evidence, не использованное при построении соответствующей линзы.
- **Randomness:** node2vec seed sensitivity не считать нулевой; фиксировать версию runner, зависимости, численные допуски и порядок article IDs.
- **Serving/privacy:** derived vectors и source text в restricted Drive, не на public GitHub. Публичный сайт и release — отдельный будущий Stage decision.
