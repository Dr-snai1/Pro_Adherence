Выходы `canonical_articles.jsonl.gz`, `source_records.jsonl.gz`, `identity_decisions.jsonl.gz`, `citation_links.jsonl.gz`, `author_observations.jsonl.gz`, `affiliation_observations.jsonl.gz` остаются неизменными. Не пересобирать Stage2, не повторять поиск и не читать данные на историческом диске C: владельца.

Citation evidence: **2 437 863** наблюдений ссылок, из них **406 811** `exact_doi`, **223** `ambiguous_doi`, **2 030 829** `unresolved`. Число `exact_doi` — количество **наблюдений**, не утверждение о 406 811 уникальных рёбрах. Raw cited-reference lists у APA RIS **не предоставлены**: это `not_exposed`, а не нуль цитирований. Из PubMed источника сохранены **86 book-family**, APA — 3 `Retracted Article` и 19 `Peer-Reviewed Status-Unknown`, WoS — 413 `NR/CR` mismatch с gap 584. Флаги не терять и не объявлять автоматически критериями исключения.

Любая линза строится по **canonical_article_id**, а не по 87 511 строкам источников. Перечень допустимых статей (`article_eligibility_policy`: journal-only versus сохранённые books) и политика выбора конфликтующих title/abstract значений между источниками — научные решения владельца; до них не подменять текст самым длинным или произвольно приоритетным. Сначала отчёт о покрытии текстом: `both_title_abstract`, `title_only`, `abstract_only`, `missing_both` по базе, family, году, флагам и каждой canonical group; агрегаты данных здесь **не измерены**.

## 2. Единый промежуточный контракт

`text_input.parquet`: `corpus_release_id, article_id, chosen_source_record_id, title, abstract, language, text_policy_id, source_record_ids, has_title, has_abstract, text_sha256, access_class`. Возможные конфликты выбора текста вынести в отдельный `text_conflict_report`.

`citation_graph_nodes.parquet`: полный approved `article_id` roster, `family`, `has_observed_outgoing_reference_list`, `has_resolved_in_or_out_edge`, `isolate_reason` (`coverage_unknown` / `no_observed_resolved_edge` / другое без научного вывода).

`citation_graph_edges.parquet`: `source_article_id, target_article_id, edge_provenance_refs, raw_reference_count, unique_edge_key, source_coverage`, только по `exact_doi` со связью к source_record + ordinal + raw SHA. Сохранить отдельно `ambiguous_citations` (223) и `unresolved_citations`; никакой arbitrary target, никакого заполнения APA ссылок. **Открыто владельцу:** направленный или ненаправленный graph для node2vec и вес/дедупликация повтора ссылки в нескольких исходных базах. До решения можно **сравнивать варианты в пилоте**, не закрепляя научный основной graph.

Каждый compute asset обязан иметь: `asset_type, asset_id, input_artifact_ids, corpus_release_id, code_ref, config_ref, model_ref_id (nullable), model_identity_hash (nullable), runtime_environment_ref, seed_policy, output_uri/hash, quality_report_id, status, created_at, computation_signature`. Model-backed => non-null immutable `model_identity_hash`. Никаких перезаписей принятых outputs. Для model identity: HF repository + **full immutable revision** + file digests, tokenizer/adapters digests, library/runtime lock; не `main` как scientific ID. Для **самого citation_graph** как non-model asset `model_ref_id/model_identity_hash=null`; **обученный node2vec embedding — model-backed asset**, его run/trained-model identity (точный graph snapshot + настройки, seed, реализация и checksums) обязана быть закреплена в non-null `model_ref_id/model_identity_hash` согласно общему compute-контракту.

Выход каждой линзы: `article_embeddings.parquet` (или Arrow shards): `article_id, representation_artifact_id, lens_id, vector: fixed_size_list<float32>[dim], text_or_graph_coverage_status, model_identity_hash, config_ref, input_hash`. Отсутствующий вектор — явный `missing`, не нулевой/fake vector. `neighbours.parquet`: `representation_artifact_id, article_id, neighbor_article_id, rank, distance_or_similarity, metric, k, filter_policy, index_ref, exact_or_ann`, отдельный набор для каждой линзы; сравнивать только на пересечении eligible/observed articles. Neighbour overlap — сравнение методов, **не независимая научная валидация**. Валидация ANN — измерение recall@k относительно exact subset или полного exact как предписано архитектурой.

## 3. Линзы и ещё не утверждённые параметры

### PubMedBERT — semantic
**Зафиксировано решением владельца 2026-11-09:** PubMedBERT Base, предобученная только на аннотациях PubMed (а не abstract+fulltext), размерность 768; из последнего скрытого слоя получаем **ДВА самостоятельных вектора: CLS и masked mean**, оба храним и проверяем отдельно; вход title + собственный маркер-разделитель токенизатора + abstract; не более **512 токенов на один проход**, длинный текст разбивается на фрагменты, без незаметного удаления хвоста; **fine-tuning не выполняем**. MetSyn не копируется. Технический кандидат модели: `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract` (бывший PubMedBERT-abstract), бесплатные веса MIT; точную immutable revision, tokenizer и SHA нужно закрепить до вычислений. [Model card](https://huggingface.co/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract). Принято два pooling-режима, **ни один пока не выбран в качестве единственного основного**.

**Проверка:** одинаковые статьи, текст и токенизация для двух pooling-конфигураций; два `N×768` артефакта с разными config signatures, полный список article_id, finite values, тест правильного CLS и masked mean, исключение padding, корректность разделителя и неусечённого охвата длинного текста; измеряемые границы CPU/GPU. Никакого автоматического дообучения. Результаты MetSyn не являются эталоном.

### Длинные аннотации: варианты агрегации фрагментов (ещё не выбраны)

**Фиксировано:** 512 токенов на один вызов Base-модели, включая специальные токены и название там, где оно присутствует. Длинную аннотацию обрабатываем несколькими вызовами, ничего не отбрасываем; на каждом фрагменте доступны оба выхода (CLS и masked mean) из последнего слоя. Каждый вариант должен давать один итоговый вектор 768 чисел для статьи **по каждой из двух ветвей**.

**Вариант A — равноправные фрагменты:** среднее от векторов всех фрагментов отдельно для CLS и Mean. Простота и дёшево; очень короткий завершающий фрагмент получает такой же вес, как полный.

**Вариант B — веса по длине фрагмента:** усреднить векторы фрагментов пропорционально числу содержательных токенов. Короткий хвост меньше влияет; для mean-векторов это может быть близко к объединению токенов всех фрагментов, но **не идентично** обработке всей статьи единым контекстом, потому что модель видит ограниченные окна. Для CLS-векторов веса по длине — отдельная гипотеза, не очевидная истина.

**Вариант C — акцент на начале:** брать первый фрагмент или дать ему больший вес, поскольку в структурированных аннотациях цель и исходная проблема часто сообщаются в начале. Дешевле, но рискует недооценить выводы и поздние фрагменты; игнорирование хвоста противоречило бы принятому решению.

**Вариант D — обучаемое объединение:** отдельная модель решает, какие фрагменты важнее. Дороже и требует обучающих примеров; сейчас не входит в принятый режим «не дообучаем», не предлагается как baseline.

**Дополнительный выбор перед пилотом:** повторять название в каждом фрагменте или включить его только в первый; делить строго по токенам либо по границам предложений; делать перекрытие соседних окон или нет. Повторяющееся название меняет его влияние на итоговое среднее, overlap повторно учитывает часть текста и увеличивает время. Для CLS и Mean можно применить один график фрагментов, но способ объединения их векторов обсуждать раздельно. Окончательное решение не принято.

### Научное сравнение настроек PubMedBERT

Теперь не открытая развилка: предобучение **abstract-only**, Base 768, **CLS и masked mean вместе**, последний слой, title+sep+abstract, 512 на проход с фрагментами, без fine-tuning. Открытые отдельные методологические вопросы: **как собрать несколько фрагментов в один вектор статьи**, нужно ли включать `[CLS]` и `[SEP]` в среднее (padding всегда исключаем), как нормализовать векторы и измерять близость, что делать с отсутствующей аннотацией или несколькими исходными версиями. Фрагменты требуют дополнительного правила: повторяем ли название в каждом фрагменте, сохраняем ли порядок и как учитываем длину фрагментов. Эти решения не следует подменять defaults.

**План методической проверки (частично уже принят):** одновременно вычислить CLS и masked mean из одних и тех же выходов последнего слоя, затем сравнить полученные тематические окружения на одинаковом наборе статей. На фиксированной внешней содержательной выборке (предложение 30–50 случаев, пока не утверждено) оценить смысловые ошибки/сильные стороны; сравнение с node2vec или SPECTER2 не является независимой валидацией. Оставшиеся решения (фрагменты, нормализация, пропуски) до запуска согласовать отдельно.

### node2vec — structural
**Уже принято:** **node2vec**, именно на citation graph; DeepWalk и GraphSAGE сняты как primary alternatives. **Предварительная техническая конфигурация только для benchmark**, не научный default: `dim=128, walk_length=40, walks_per_node=10, context_window=10, p=1, q=1, epochs=1, seed=20261031`. Для sensitivity минимум вариант `p/q` при фиксированном графе и 2–3 random seeds; окончательные `p,q,dim,weight,direction/isolate` — владелец. Сохранить graph_snapshot_id, deterministic sorted node mapping, edge dedup policy, seed, exact package versions, walker implementation, `graph_hash`, isolated component policy. Directed versus symmetrised training нельзя менять без отдельного scientific config. [Original Stanford reference defaults](https://github.com/snap-stanford/snap/blob/master/examples/node2vec/node2vec.cpp) (80 walk length, 10 walks/node, 128 dim, p=q=1) — это только **внешний технический ориентир**, не утверждённые параметры.

**Проверка:** отсутствие edge без verified target, отсутствие self-loop/duplicate policy anomalies, 223 ambiguous DOI не стали рёбрами; подсчёт unique graph edges, component/isolates, degree distributions по данным и источникам; seed sensitivity и same-config deterministic replay/tolerance. Нельзя объяснять изоляцию отсутствием цитирований в реальном мире при неполных источниках. Если node2vec не даёт осмысленного вектора изолированному узлу, фиксировать `missing_structural`.

### SPECTER2 — semantic + citation-trained prior
**Уже принято:** отдельная SPECTER2 lens; она **не подменяет** PubMedBERT и node2vec. Модель использует title+abstract при inference; её структурный компонент происходит из **citation-informed pretraining**, а не из подгрузки текущего citation graph Stage2. **Технический кандидат**: `allenai/specter2_base` + proximity/retrieval adapter `allenai/specter2`, для статьи `title + tokenizer.sep_token + abstract`, truncation max_length=512, первый токен last_hidden_state. [Official SPECTER2 documentation](https://github.com/allenai/SPECTER2) / [model card](https://huggingface.co/allenai/specter2_base). **Требует фиксации** base+adapter revisions/digests, `transformers`/`adapters` compatible versions и owner-approval для proximity adapter как scientific task variant; другие adapters означают другую lens configuration. При обычной BERT-base конфигурации ожидается 768 dim, подтвердить непосредственно по pinned model config до исполнения.

**Проверка:** exact base/adapter identity, тест `title/abstract` concatenation и 512-token truncation, `N×dim`, no NaN, same-revision reproducibility, сравнение neighbourhood coverage отдельно от семантической/структурной линз. Не использовать собственный citation graph как ещё один вход SPECTER2 без научного решения.

## 4. Порядок реализации и stop/go

**Gate P0 (сейчас, без compute):** сохранить идентичность frozen Stage2, закрепить настоящую immutable revision весов abstract-only Base, научные решения 1–7 от 2026-11-09 и **два** конфигурационных результата; согласовать способ агрегации фрагментов >512 и специальные токены/нормализацию, правила неполного текста и выбор источника. GO к вычислительному пилоту только после отдельного разрешения владельца. Нет необходимости искать или копировать MetSyn.

**Gate P1 (один малый пилот, только после разрешения):** **примерно 1 000 canonical групп**, детерминированная стратификация source presence, год, journal/book, abstract availability, citation degree/isolation и APA flags; одна малая component graph neighbourhood при необходимости проверяет edge cases. Сначала проверить input coverage и graph census, затем inference PubMedBERT и SPECTER2 последовательно, node2vec два seed-повтора на одном graph config. Измерять tokens/article, p50/p95 truncation, docs/sec, peak CPU/GPU RAM, walltime, dollars=0 при бесплатной среде, output bytes. Не трактовать 1 000 как научный discovery sample.

**Gate P1 checks:** 100% expected article_id coverage *как статус* (включая missing), никакой дубликации id, zero nonfinite vectors, 100% source lineage, identity hash и правильная размерность, traceable edge counts, 0 ambiguous auto-targets; partial text/graph coverage измерены, не считаются `zero`; repeat within numerical tolerance, node2vec seed variation quantified. Ручная внешняя содержательная проверка фиксированной небольшой выборки. **STOP** при invalid model pin, неверном graph target, невоспроизводимом input/ID alignment, memory overflow.

**Gate P2 (отдельная санкция на полный run):** последовательные offline runs с чанками/checkpoints, `PubMedBERT` → `SPECTER2` → `node2vec` либо изменение очередности по измеренному ресурсу. Каждый — отдельный immutable asset с собственным manifest. Порча одной линзы не инвалидирует готовый snapshot другой. Подготовить index/exact-neighbour computation specs для будущего Stage4; сравнение top-k neighbour sets на общем observed coverage (не валидирует ни одну линзу). Только после полного private readback/hashes и developer проверки разными методами — QA04 на крупном интегрированном рубеже. Нет автоматического Stage transition/release.

## 5. Ресурсы: инженерная оценка, не измеренный benchmark

Пусть `N=57 293`. Два PubMedBERT-вектора (CLS и Mean) отдельно, float32, по **57 293×768×4=176 004 096 B ≈168 MiB**, суммарно ≈336 MiB; SPECTER2 с dim=768 ещё ≈168 MiB; node2vec с пока НЕ утверждёнными 128 dims — **29 334 016 B ≈28 MiB**. Всего только dense floats ≈**532 MiB**, плюс metadata, исходники, веса, промежуточные фрагменты, индексы и граф. Полную попарную матрицу `N×N×4` ≈13.1 GB не создавать. Вычисление двух pooling-ветвей возможно **за один проход модели на тех же токенах**, но понадобятся два набора сохранённых векторов.

| Задача | Пилот | Полный объём: предварительная вилка | Ресурсный риск |
|---|---|---|---|
| Таблица текстовых входов + graph | метаданные ~1k и edge checks | 1–4 h CPU подготовки/проверок | 16 GB RAM минимум, 32 GB комфортно; 10–25 GB свободного scratch |
| PubMedBERT inference | 1k статей, CPU либо бесплатная GPU | GPU ~0.5–3 h; CPU заметно дольше (~6–36 h) | ~8–16 GB VRAM на batch 8–32/до 512 tokens, 16–32 GB host RAM |
| SPECTER2 inference | 1k статей после model pin | GPU ~0.5–3 h; CPU ~6–36 h | batch/VRAM примерно аналогично PubMedBERT; base + adapter |
| node2vec | 1k sample graph для API/seed checks; графовая репрезентативность ограничена | ~0.5–8 h CPU, сильно зависит от edge aggregation/walk corpus | 16–32 GB RAM ориентир, Python graph object может увеличить потребление |
| Neighbours | exact sample и ANN recall audit | ~0.5–3 h после vectors | RAM ~8–16 GB, без полной dense N×N матрицы |

Значения времени — **оценки сценария**, не обещания. Batch length, GPU type, missing abstracts, model adapter и реализация walks изменяют скорость на порядок. Экстраполяция только из реального P1: `T_full ≈ T_pilot × (N_eligible/N_pilot_eligible)` для transformer lane + загрузка моделей/фиксированный overhead; для node2vec повторно оценить на полном графе — малый подграф не доказывает full-graph memory profile.

**Расходы:** вариант A — локальная CPU/GPU или бесплатный одолженный/институциональный compute: **$0 внешних счетов** (время/электроэнергия не нулевые). Вариант B — отдельный разрешённый одноразовый remote GPU: ориентир текущих оферт 16GB RTX A4000 от **$0.25/h** и 24GB L4 от **$0.49/h** ([Runpod A4000](https://www.runpod.io/gpu-models/rtx-a4000), [L4](https://www.runpod.io/gpu-models/l4), цены/доступность зависят от региона и типа), условные 2–10 GPU-hours ≈ **$0.5–$5** *только GPU* плюс CPU/диск/выгрузка/хранение. Эта сумма **не является одобренным бюджетом, live quote или оценкой полной стоимости**. Никакого автоматического provisioning/billing. **Выбранный вычислительный режим:** закрытый анализ для собственного исследования на локальной машине или одноразово арендованном компьютере, без передачи текста стороннему сервису генеративного ИИ и без публикации исходных записей. Арендованный компьютер технически означает размещение рабочей копии данных на этой машине, но не передачу данных в публичный API. Дополнительные повторяющиеся этапы проверки лицензий, юридические gate или отдельное разрешение на каждый технический шаг не включаются в рабочий pipeline. Расходы на платный compute остаются отдельным решением владельца.

## 6. Важные дефекты/смещения и раздельная валидация

- **Text missingness / selection bias:** абстракт отсутствует у части корпуса; политику title-only и конфликтов источников утверждать отдельно. Качество neighbour similarity и coverage сравнивать стратифицированно, отсутствие не маскировать.
- **Citation observation bias:** APA no cited-reference lists, WoS 413 NR/CR inconsistencies; node2vec graph reflects *observed resolved links*, не полную сеть. Наличие/отсутствие edge нельзя использовать для вывода о неизмеренной исторической citation activity.
- **DOI ambiguity:** 223 наблюдения ссылки без unique target; не добавлять в graph; хранить `ambiguous_doi`.
- **Family/retraction:** 86 book-family сохранены, APA retractions/unknown flags не исчезают. Решение включения в научный article-only universe остаётся owner-level.
- **SPECTER2 independence:** обученность на citation relations НЕ независимая проверка node2vec; сравнение линз — объект анализа. Внешняя manual relevance/held-out validation должна содержать evidence, не использованное при построении соответствующей линзы.
- **Randomness:** node2vec seed sensitivity не считать нулевой; фиксировать версию runner, зависимости, численные допуски и порядок article IDs.
- **Serving/privacy:** derived vectors и source text в restricted Drive, не на public GitHub. Публичный сайт и release — отдельный будущий Stage decision.

## 7. Один следующий шаг и вопросы владельцу

**Выполненная подготовка 03 без расчётов корпуса:** в действующей ветке реализованы [строгие проверочные контракты](../../src/pro_adherence/stage3_contracts.py), [синтетические регрессионные тесты](../../tests/test_stage3_contracts.py) и [отдельный бесплатный CI](../../.github/workflows/stage3-contracts.yml). Эти инструменты требуют явного выбора источников текста/состава статей, учитывают статус недостающего текста и изолированных узлов, запрещают выдумывать DOI target, валидируют raw SHA/ordinals цитирований, отсутствующие векторы и обязательные model identity pins. Они **не производят** embedding и не запускают node2vec. Кодовый тест не является разрешением научной конфигурации или compute.

**Ближайший предмет методологического обсуждения:** как усреднять результаты фрагментов длинной аннотации (одинаково или пропорционально числу смысловых токенов; повторяется ли title), какие спецтокены входят в masked mean, как поступать с отсутствующими аннотациями и нормализацией. Решения 1–7 уже приняты и не требуют повторного согласования. После этого техническая подготовка пилота (только отдельное owner compute permission).

**Открытые решения перед пилотом:** (1) один контракт агрегации фрагментов и masked-mean special tokens; (2) нормализация, отсутствующие аннотации, выбор текста при конфликте нескольких источников и 86 PubMed book-family; (3) scientific graph/node2vec choices; (4) SPECTER2 adapter; (5) разрешение небольшого пилота ~1 000 статей, предпочтительно бесплатно. CLS и Mean — **оба утверждены**, abstract-only Base и остальные параметры 1–7 — **уже утверждены**. Данных пока не считали.
