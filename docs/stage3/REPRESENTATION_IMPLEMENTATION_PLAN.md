## 3. Линзы и ещё не утверждённые параметры

### PubMedBERT — semantic
**Зафиксировано решением владельца 2026-11-09:** PubMedBERT Base, предобученная только на аннотациях PubMed (а не abstract+fulltext), размерность 768; из последнего скрытого слоя получаем **ДВА самостоятельных вектора: CLS и masked mean**, оба храним и проверяем отдельно; вход title + собственный маркер-разделитель токенизатора + abstract; не более **512 токенов на один проход**, длинный текст разбивается на фрагменты, без незаметного удаления хвоста; **fine-tuning не выполняем**. MetSyn не копируется. Технический кандидат модели: `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract` (бывший PubMedBERT-abstract), бесплатные веса MIT; точную immutable revision, tokenizer и SHA нужно закрепить до вычислений. [Model card](https://huggingface.co/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract). Принято два pooling-режима, **ни один пока не выбран в качестве единственного основного**.

**Проверка:** одинаковые статьи, текст и токенизация для двух pooling-конфигураций; два `N×768` артефакта, конечные числа, тест правильного CLS и masked mean; **для Mean маска содержит только обычные токены текста, исключая CLS, SEP, остальные специальные символы и padding**. CLS-ветвь берёт последний hidden state токена CLS. Корректный разделитель, неусечённый охват длинного текста и численные проверки; без fine-tuning.

### Приоритет источника PubMed → WoS → APA (утверждено 2026-11-09)

Сначала рассматривать **целые записи** canonical group с title и abstract; выбирать первую по приоритету PubMed, затем WoS, затем APA. При отсутствии complete записи — брать первую запись с title по тому же порядку (с явным флагом `title_only` только когда abstract действительно нет ни в одной записи). Не смешивать название из одной базы с аннотацией из другой автоматически. Иные пограничные случаи маркировать для адресной обработки, не заводить новый обязательный этап согласования для каждой статьи. Техническая функция `choose_pubmedbert_source_priority` детерминированно формирует выбор. Сохранять source_record_id, исходный порядок базы и причину fallback, считать распределение выбранных текстов по базам.

### Статьи без аннотаций — вариант В (утверждено 2026-11-09)

Если хотя бы одна исходная запись canonical group содержит abstract, не допускать вычисление по одному названию автоматически: нужен явно выбранный корректный исходный текст/правило конфликта между базами. Если **ни одна** исходная запись не содержит abstract, но есть title — вычислить **два** независимых PubMedBERT-вектора `CLS` и `masked_mean` по одному title, сохранив `text_state=title_only` и `title_only_vector=true`; отсутствие abstract не восстанавливается и не маскируется. Если отсутствует и title, установить `missing_input` и null vector. Не назначать title-only штраф/искусственную весовую поправку и не исключать такие статьи без отдельного научного решения.

**Отчёт после разрешённого расчёта:** отдельные абсолютные числа/проценты title-only от **57 293 canonical articles**, от eligible и от готовых PubMedBERT-векторов; помимо этого — число случаев `requires_source_resolution`, когда выбранный title-only источник имеет другой source record с аннотацией. Разбивка по году, source family и типу записи; отдельно показать качество / контекст ближайших публикаций для title-only на позднем этапе оценки, без запуска отдельного пилота для принятия решения. Сохранить lineage выбранного source record, versioned config и фактический текстовый статус. Никакой процент не считать до обработки реальных данных.

### Длинные аннотации — утверждённая методика 2026-11-09

**Решение владельца:** вариант **Б, без отдельного сравнительного пилота А/Б**. При длине input >512 токенов формировать несколько фрагментов, **предпочитая границы завершённых предложений**; каждый фрагмент — отдельный inference того же frozen PubMedBERT Base. Для обеих самостоятельных ветвей CLS и masked mean рассчитывать итоговый вектор статьи **как средневзвешенное векторов фрагментов**, вес каждого фрагмента — **число его содержательных токенов** (без padding и специальных служебных токенов). Более короткий остаточный фрагмент влияет меньше. **Не сравнивать А и Б перед использованием, не подменять Б простым равным средним.**

**Реализация:** точным tokenizer модели определить бюджет в 512 токенов, включая CLS/SEP и маркер после названия; greedily собирать последовательные предложения, пока следующий полный sentence не переполнит бюджет, затем начинать следующий chunk. Если отдельное предложение длиннее свободного бюджета нового чанка — делить **только этот случай** по границам токенов и считать такие вынужденные разрезы. Содержимое обрабатывать **целиком, в исходном порядке**. Не делать дублирующих перекрытий и повторного учёта токенов; в техническом baseline название появляется один раз в первом фрагменте и не повторяется в следующих, чтобы не изменять вес заголовка искусственно. Перед inference ещё раз проверить фактическую длину целиком закодированного chunk <=512. Если токенизация по границам предложения даёт изменившееся число токенов при склейке, перепаковать; не обрезать текст молча. Учитывать смещения token start/end и число содержательных токенов. Строго проверить полное покрытие: каждый исходный смысловой токен ровно один раз.

**Ограничение методики:** это сохранение текста без усечения, а не математически эквивалентное чтение всей статьи в одном контексте Transformer. Вес по длине для CLS тоже является принятой исследовательской эвристикой; она не объявляется оптимальной или доказанно лучшей.

### node2vec — structural
**Уже принято владельцем (2026-11-10):** одна основная конфигурация node2vec: `dim=128`, `p=1`, `q=1`, `walk_length=40`, `walks_per_node=10`, `context_window=10`, `epochs=1`, `seed=20261031`; **2026-11-12 владельцем дополнительно утверждены `negative=5`, `sample=0.001` для Word2Vec skip-gram backend** (`sg=1/hs=0` как явные технические параметры; полное CPU-обучение не разрешено); **ненаправленный training graph** на уникальных неупорядоченных парах подтверждённых цитирований с бинарным `weight=1` и без self-loops. **Исходные направленные citation links сохраняются** отдельным графом без потери provenance. Изолированные/непредставленные в наблюдаемой сети статьи получают `missing_structural`/null, без искусственных связей или fake-zero vectors; отсутствие APA cited references не равняется отсутствию научных связей. На каждую реально полученную 128-мерную node2vec embedding сохранить **raw vector до нормализации, raw L2 norm, отдельный unit vector**; основное сходство — **cosine на L2-normalized output**; не уничтожать исходный масштаб/направление. Научно принятая конфигурация — **стартовая, не утверждение оптимальности** одной эпохи или длины маршрута. Код и отчёты должны фиксировать графовый snapshot/hash, directed/undirected derivation, source edges/counts, deterministic ID mapping, implementation/library versions, seed, exact config, isolate count, vector completeness и численные проверки. Дополнительная техническая проверка устойчивости и seed-replay не превращается в отдельный научный пилот; менять значения без нового методологического решения нельзя. DeepWalk и GraphSAGE не входят в основные модели.

**Проверка:** 100% source→canonical provenance и только exact DOI targets; никаких ambiguity→edge или fake APA links; повторные источники не меняют binary weights; направленный source и ненаправленный training graph сохраняются раздельно с совпадающим числом учтённых наблюдений; 0 duplicated undirected pairs / 0 self loops в training graph; графовая connectedness и isolated statuses в отчёте, явный `missing_structural`, не нулевой вектор. Для node2vec output — dim=128, finite raw/norm/unit, norm>0, unit≈1, raw≈norm×unit, metric=cosine. Проверить deterministic replay и как минимум seed sensitivity при плановом пилоте; результат seed-проверки не означает поиск альтернативного p/q. Не интерпретировать отсутствие observed links как доказательство отсутствия реальных цитирований.

### SPECTER2 — semantic + citation-trained prior
**Принято владельцем 2026-11-10:** SPECTER2 — третья самостоятельная семантико-структурная линза, но не потребитель текущего citation graph: структурная информация уже есть в citation-informed pretraining. **Использовать `allenai/specter2_base` + `allenai/specter2` proximity/retrieval adapter** (а не classification/regression/adhoc). При inference `title + tokenizer.sep_token + (abstract or "")`, источник выбран полностью по PubMed → WoS → APA с приоритетом записи title+abstract, title-only когда нет abstract во всей canonical group, конфликт abstract-only из другой записи => `requires_source_resolution` без склейки полей. Вход `max_length=512` с `truncation=True`, без фрагментации; **строго учитывать и отчитываться** по каждой публикации: untruncated token count, actual encoded token count, tokens lost; после полного расчёта вывести count/share truncated от canonical и ready, lost tokens aggregate/distribution, title-only coverage. Один итоговый `float32[768]` из `output.last_hidden_state[:,0,:]` после активированного proximity adapter; `fine_tuning=False`. **L2 после формирования полного article vector, cosine similarity**, сохранять raw vector со всеми координатами, исходную L2-норму и отдельную нормализованную копию. Идентичности base, adapter, tokenizer и совместимые runtime версии закрепить полными immutable revisions + artifact digests **до inference** (technical preflight, а не новая развилка владельцу); не подменять `main` или не проверенным модельным набором. [Официальный SPECTER2 model card](https://huggingface.co/allenai/specter2_base) / [adapter documentation](https://huggingface.co/allenai/specter2). Никакого обязательного сравнительного пилота альтернативных адаптеров.

**Проверка SPECTER2:** обязательно активировать нужный proximity adapter; проверить полные revision SHA и file digests для base, adapter и tokenizer, pinned compatible adapters/transformers runtime; синтетические тесты точного source priority и запрета cross-record склейки; `title + SEP + abstract` и title-only, `max_length=512`, один final first-token vector размерности 768; отчёт о потере токенов при 513+ и отсутствие потерь при <=512; null/status при отсутствии текста. L2/cosine: finite raw, norm>0, unit≈1, raw≈norm×unit. Same-revision deterministic replay, downstream quality отдельно; не добавлять Stage2 citation graph в inference SPECTER2.

## 6. Важные дефекты/смещения и раздельная валидация

- **Text missingness / selection bias:** утверждено сохранять title-only статьи с явным статусом. После обработки измерять `title_only_count` и проценты от всего canonical roster, eligible и ready vectors, в разрезе года, исходной базы и типов публикаций. Проверить содержательно качество окружения title-only статей отдельно, чтобы видеть эффект неполноты текста, **без автоматического исключения или штрафа**. Если abstract имеется в другой исходной записи, запись не признаётся title-only до разрешения политики выбора текста.
- **Citation observation bias:** APA no cited-reference lists, WoS 413 NR/CR inconsistencies; node2vec graph reflects *observed resolved links*, не полную сеть. Наличие/отсутствие edge нельзя использовать для вывода о неизмеренной исторической citation activity.
- **DOI ambiguity:** 223 наблюдения ссылки без unique target; не добавлять в graph; хранить `ambiguous_doi`.
- **Family/retraction:** принято владельцем 2026-11-10: весь frozen corpus неизменен; derived main journal cohort на canonical_article_id. Journal source хотя бы один => eligible кроме подтверждённой retraction; исключительно книжные группы excluded_book_only; подтверждённая retraction в любом source member => excluded_retracted; только unknown family => requires_family_resolution. APA unknown peer-review и WoS NR/CR mismatch включаются с диагностическими флагами. Source-level 86/3/19/413 — не численность исключённых canonical groups. Исключённые группы и их observed direct citations остаются в полном immutable directed graph; node2vec training graph строится только по primary eligible endpoints. Три линзы разделяют eligibility policy, но различаются готовностью эмбеддингов. На полном корпусе вывести точные counts по статусам и флагам; не высчитывать их без фактического readback.
- **SPECTER2 independence:** обученность на citation relations НЕ независимая проверка node2vec; сравнение линз — объект анализа. Внешняя manual relevance/held-out validation должна содержать evidence, не использованное при построении соответствующей линзы.
- **Randomness:** node2vec seed sensitivity не считать нулевой; фиксировать версию runner, зависимости, численные допуски и порядок article IDs.
- **Serving/privacy:** derived vectors и source text в restricted Drive, не на public GitHub. Публичный сайт и release — отдельный будущий Stage decision.
